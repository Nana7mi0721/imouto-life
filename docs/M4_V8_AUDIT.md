# M4 v8 语义专项审计

结论先行：**普通变量 8（magic `2000008`）不是行动力，而是“今晚可活动到几点”的夜间时间上限**，用 23/24/25/26 的扩展时钟记法表示（23:00、24:00、01:00、02:00）。它只被时钟/夜命令/就寝三个事件读写，和 Sys 变量 104/105 的定屏结论无关。

## 证据（静态解析 `BasicData/CommonEvent.dat`，opcode 121/111 操作数）

| 事件 | 标题 | 指令 | 含义 |
|---|---|---|---|
| CE243 | 時刻表示 | pc52 `v8 = 25`（周五分支） | 周五夜上限抬到 25:00 |
| CE243 | 時刻表示 | pc57 `v8 = 25`（周六日分支） | 周末夜上限抬到 25:00 |
| CE245 | 夜コマンド | pc58 `if v8 == 24 || v8 == 25` | 仍在夜间，进入「処理継続」；否则「就寝時間」 |
| CE245 | 夜コマンド | pc399 `v8 += 2` | 喝咖啡延长 2 小时 |
| CE245 | 夜コマンド | pc432 `v8 += 1` | 喝红茶延长 1 小时 |
| CE246 | ┣コミュニケーション | pc128 `if v8 == 24 || 25 || 26` | 只有 24:00–02:00 档还允许继续交流 |
| CE251 | ┗就寝 | pc174 `v8 = 24`（var10/11/12 命中分支） | 次日上限 24:00 |
| CE251 | ┗就寝 | pc177/180 `v8 = 23`（分档分支） | 次日上限 23:00 |
| CE251 | ┗就寝 | pc183 `v8 = 24`（else 分支） | 次日上限 24:00 |

opcode 121 的复合位 `0x100` 是加法（`crates/wolf-vm/src/exec.rs` `compound`），所以 pc399/pc432 是“上限 +2 / +1 小时”，不是赋值。

## 全局扫描

- 写 v8 的事件恰好是 **CE243 / CE245 / CE251**，共 8 条 121。
- 读 v8 的事件恰好是 **CE245 / CE246**，共 2 条 111（分别比较 24/25 与 24/25/26，均为等值比较）。
- 没有事件把 v8 与行动力阈值、日期或金额比较。

## 对既有文档的修正

- `docs/M3_MANUAL_ALIGNMENT.md` 原记“CE243 周五/周六写 2000008=25、CE245 ±1/±2、CE251 读 23/24”方向正确，但把它当作“就寝时间存疑”点；本审计把完整读写集合与 24/25/26 上限语义钉死。
- 官方存档 v8=23/24 是当天的夜间上限快照，不是行动力；M3 的读档断言不需要改。
