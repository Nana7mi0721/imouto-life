# M6 输入层对等（opcode 123 / 125 / 126、改键、按键重复）

本轮把「玩家按键 → 脚本看到什么」这条链路从近似实现还原成数据本身规定的行为。
四条独立证据源互相印证：`CommonEvent.dat` 里开发者自己写的 `103` 调试注释、
第三方独立解析库 `wolfrpg-map-parser 0.4.1` 的字段结构、游戏内实测（headless
回放与截图同源），以及原版 `お読みください.txt` / 说明书第 1 页的按键说明。

## 1. `123 キー入力` 的第二个参数是打包的「选项字」，不是键位掩码

旧实现把 `123` 的第二个参数当成「允许的键位位掩码」并且**完全忽略**它，永远回答
「当前按住的任意键的键码」。实测该参数是 4 字节打包结构（与
`wolfrpg-map-parser` 的 `InputKey` / `BasicOptions` 一致）：

| 位 | 含义 |
|---|---|
| 0..3 | 方向选择：0 无、1 四方向、2 八方向、3 上、4 下、5 左、6 右、7 上下、8 左右 |
| 0x10 | 接受决定键 |
| 0x20 | 接受取消键 |
| 0x40 | 接受副键 |
| 0x80 | 等待输入（阻塞到有可用按键） |
| 8..11 | 设备：0 逻辑键、1 键盘原始键、2 手柄、3 鼠标 |

**数据内证据**（全部来自脚本作者自己的注释）：

| 掩码 | 解码 | 脚本注释 |
|---|---|---|
| `0xB0` (176) | 等待 + 决定 + 取消 | CE118 `決定かキャンセルか、だけ受付する`（只接受决定/取消） |
| `0xB8` (184) | 等待 + 决定 + 取消 + 左右 | CE84 分支只比较 4（左）和 6（右） |
| `0xB7` (183) | 等待 + 决定 + 取消 + 上下 | CE127 |
| `0xF1` (241) | 等待 + 决定 + 取消 + 副键 + 四方向 | CE65 `サブキーを押したら終了する場合` |
| `0x10` / `0x20` / `0x40` | 仅决定 / 仅取消 / 仅副键 | CE59 三个独立单键轮询 |
| `0x11` (17) | 四方向 + 决定，不等待 | 常见移动轮询 |
| `0x101` / `0x200` | 设备=键盘 / 设备=手柄 | CE132 改键捕获 |

本作 `CommonEvent.dat` 共 93 条 `123`，全部落在该编码内（无未解值）。

### 1.1 掩码过滤（玩家可见差异）

`crates/wolf-game/src/key.rs` 新增 `accepts()` / `code_for()`：轮询只回报它请求
的键。例：CE59「キー連打で中断できるウェイト」用 `0x10`/`0x20`/`0x40` 分别检查
决定/取消/副键——旧实现里按住方向键也会让三个变量全部非 0，于是「按方向键」也能
中断等待；现在只有真正按了对应键才算。

### 1.2 等待位 = 真正的阻塞

`0x80` 是编辑器「入力を待つ」勾选。实测 CE251 pc162 在「クリック処理」注释下
`123 [var, 0x91]`，其结果**从未被读取**，随后撤掉 pauseL 气泡、黑屏、等 1 帧：
这就是「暂停画面，等玩家点击继续」。CE249 pc257、CE297 pc32 同样用法。

旧实现从不阻塞，这些暂停被直接冲过去。现在 `123` 在等待位且结果为空时设置
`WaitState::Key` 并停在原指令，下一帧重试；`poll_waits` 每帧清除该状态。

## 2. 设备轮询与改键闭环

`0x101`（键盘）/ `0x200`（手柄）让 `123` 返回**原始键码**而不是 10/11/12。
WOLF 键盘码 = DirectInput 扫描码 + 100：Z=144、X=145、C=146（`System.sav`
默认值），手柄 301..303。CE132 的改键行把捕获值写进 Sys52..54。

实现：

- `Game::raw_keys` / `raw_pad_keys`：本帧按住的原始键码（无头路径为空）。
- `GameHost::key_code`：设备轮询返回对应设备的原始码，否则按选项字过滤。
- `wolf-cli play`：用 winit 物理键码查扫描码表（Z=0x2C→144 等），每帧写
  `game.raw_keys`；决定/取消/副键＝`live_settings().key_config` 里的 Sys52/53/54，
  再加上说明书固定的 Enter / Backspace 别名（`マニュアル01`：決定 Enter・Z・左クリック，
  キャンセル backspace・X・右クリック）。改键后**立即生效**，不需要重启。

## 3. `125 自動入力` / `126 入力切替` 的编码也修正了

两者第一字都是编辑器自己的键位字节（决定 1、取消 2、副键 4、**下 0x10、左 0x20、
右 0x40、上 0x80**），与端口内部位序不同；`126` 第二字节是模式
（0 启用、1 禁止移动、2 全部禁止），不是掩码。

旧实现把 `126` 的整个字当「禁止位」，于是地图事件 0 开场的 `126 [247]`
（= 启用全部按键）被理解成「禁止全部按键」，整局游戏之后所有 §1 轮询都读不到按键。
本轮改为按模式设置/清除禁止集，并在主机侧用 `from_wolf_bits()` 转成端口位序。

`125` 的方向位序也被翻译：CE223「位置関係により自動キー入力」用 `0x10` 表示「按下」，
旧实现读成「上」，自动输入按反方向推光标。

## 4. 顺带修正的引擎缺陷：`121` 的 0x600 / 0x700 是 min/max

CE132 音量行写 `Sys100 = max(Sys100, 0)`、`Sys100 = min(Sys100, 120)`；旧实现把
0x600/0x700 当成「赋值」，于是任何一次音量调整都会把值钉成边界值（实测 100 → 120）。
数据里 `0x600` 出现 153 次、`0x700` 49 次，配对形式都是 `[v, 下界, 0, 0x600]` /
`[v, 上界, 0, 0x700]`（如 CE36 `v3 = clamp(v3, 1, v82)`）。现已改为
`current.max(value)` / `current.min(value)`。

## 5. 设置界面交互闭环

本轮实测并固化为测试：

- 九行光标可用方向键移动，帮助行随行变化；取消可退出。
- 音量行：左/右即时改 Sys100/102，`Game::frame` 检测到变化就把新增益送进混音器
  （原版在设置界面里改音量就是即时可听的）。
- 改键行：捕获键盘原始码写入 Sys52..54，`live_settings()` 立刻反映。
- リセット 行写回默认（144/145/146/301/302/303、音量 100）。
- 退出游戏时 `play` 仅在音量有变化时写 `Save/System.sav`（既有逻辑）。

## 7. 不做的部分

- **PlayerTouch（trigger 3）**：唯一带该触发器的 `Dungeon.mps` / `SampleMapB.mps`
  是编辑器样例，本作 SysDatabase 注册的 5 张图（TitleMap / SampleMapA / Map003 /
  Map024 / Map031）全部没有 trigger-3 页。`m6_input_parity` 用数据断言锁定这一点，
  端口继续不为它建模（AGENTS.md §4）。
- **ActionKey 命中框**：端口按 WOLF 的 tile + `range extension`（左上锚定、
  `(1+扩展)×16px`）判定，与 `m3_map_click` 钉住的边界一致。画面按钮图元比 tile 框
  大/偏移（如结束按钮图元 (935,505) 90×70，命中框 (976,544) 起），这是数据本身的
  摆放，不是端口偏差；原版同样是「角色所在 tile 落在框内」才触发。
- **手柄**：本作 `125`/`126`/`123` 的手柄分支没有可用设备，`raw_pad_keys` 留空，
  改键行的「パッド」列不会捕获——与原版无手柄时一致。
