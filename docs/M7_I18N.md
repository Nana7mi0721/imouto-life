# M7 — Internationalisation (full English pack)

This milestone delivers a complete English text catalog for the shipped script and the
tooling that produces and validates it. The game data itself is untouched: a catalog only
replaces exact source strings as they leave the VM.

## Result

- Full catalog: docs/translations/en.full.tsv
- Coverage (strict check): 1218 / 1218 static strings, 0 missing, 0 unused, exit 0.
- Static strings split: 1046 message-context + 172 choice-context.
- 46 variable-dependent strings (contain \v[..], \self[..], \corgv[..], …) have no
  fixed runtime text and are intentionally outside the coverage denominator.
- Total static sites in the script: 1476.

Reproduce the check:

    cargo build -q -p wolf-cli
    ./target/debug/wolf-cli.exe translations --root work/Data \
        --check docs/translations/en.full.tsv --strict
    # coverage: 1218/1218 static (100.0%), 0 missing, 46 dynamic, 0 unused  (exit 0)

Regenerate a fill-in template at any time:

    ./target/debug/wolf-cli.exe translations --root work/Data \
        --template work/out/i18n_template.tsv

## Catalog format

UTF-8 TSV, one entry per line, source<TAB>translation:

- Lines whose first non-space character is # are comments; blank lines are ignored.
- The source column is matched against the runtime string exactly (trailing spaces
  included) after escape expansion.
- Both columns understand escapes: \n (newline), \t (tab), \r (carriage return) and
  \\ (literal backslash). This lets a source string that contains a real TAB/CR/LF occupy
  a single physical TSV line.
- Other backslash sequences are display markup and are copied through literally, not
  expanded — e.g. \c[6], \f[24], \E, \>X[...], \^. Only \n, \t, \r and \\ are treated
  as escapes.
- An empty translation column is a placeholder: the line is ignored, so an unfilled
  template can be loaded safely.
- A duplicate source keeps the last translation.

### Escaping example

A runtime line (backslash-E, then text, then a real newline in the runtime string) is
written in the catalog as one physical line, with the newline encoded as \n:

    \E哼…\n屁…<TAB>\ENgh…\nIn… my… backside…

The leading \E is literal markup; \n in the source cell expands to the real newline
before matching, and \n in the translation cell expands to a newline in the output. A
literal backslash in the runtime text is stored as \\.

## Scoped keys

Prefix the source column with [msg] or [choice] to target only messages or only choices.
A scoped entry wins over an unscoped one; the unscoped entry stays the fallback for the
other context.

    [msg]同じ台詞	Spoken line
    [choice]同じ台詞	Menu label
    同じ台詞	Both contexts

## Switching language at runtime

Pass a catalog with --translation:

    wolf-cli play   --load-save work/Data/Save/SaveData01.sav --translation docs/translations/en.full.tsv
    wolf-cli capture --load-save work/Data/Save/SaveData01.sav --event 245 \
        --translation docs/translations/en.full.tsv --frames 90 --out work/out/night_en.png

A mod directory may also contain its own translations.tsv at its root. Mod catalogs merge
in --mod order (later wins), and an explicit --translation catalog merges last, so it
always has the final say. Missing entries fall back to the original script text.

## Extending to other languages

1. Generate the template:

       wolf-cli translations --root work/Data --template work/out/i18n_template.tsv

2. Copy it, e.g. docs/translations/<lang>.full.tsv, and fill in the translation column.
   Keep every source cell byte-for-byte as generated; use \n / \t / \\ when a translation
   needs a newline / tab / backslash.

3. Validate:

       wolf-cli translations --root work/Data \
           --check docs/translations/<lang>.full.tsv --strict

   It must print 1218/1218 … 0 missing, 0 unused and exit 0.

4. Switch with --translation docs/translations/<lang>.full.tsv, or ship it as a mod's
   translations.tsv.

Because coverage is enforced against the exact set of static strings in the data, the
strict check is the acceptance gate for any language pack.

## Known limitations

- The 46 variable-dependent strings are not in the template and are not translated; they
  are assembled from runtime variables and follow the dynamic-site path.
- A handful of catalog entries originate from already-garbled bytes in the source data
  (half-width kana / private-use code points). Their translations are passed through as-is
  rather than guessed; they are cosmetic strings (a few shop labels) and do not affect the
  main dialogue.
- The English wording is a faithful, neutral adaptation; markup tokens, punctuation
  markers and trailing full-width spaces from the source are preserved where present.
- Escape expansion applies to the four documented sequences only. Display markup such as
  \c[..], \f[..], \E, \>X[..], \^ is intentionally left literal.

## Authoring pipeline (this repo)

    work/out/trans/raw_01.txt … raw_08.txt   # one line per entry, <NL>/<BS>/<TAB> tokens
    work/out/build_en.py                     # joins chunks, re-applies markup prefix + escaping
    docs/translations/en.full.tsv            # generated catalog (1218 lines)

The chunk files use <NL> for newline, <BS> for a single backslash, and <TAB> for tab. The
build script auto-prepends each row's display-markup prefix (taken from the template
source) and re-escapes it, so the generated source and translation cells stay consistent
with the template.
