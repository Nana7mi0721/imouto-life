## 3. 坐标约定

### 3.1 两个坐标

- **CE 坐标**：`CE<编号>@<pc>`。
  `_ce_full.json` 的 `id` 为 **0 基 `0..349`**，且 **`id == 数组下标 == CE编号`**（`d[245]` 即 CE245，
  **不做 +1 偏移**）；**`cmds[i].pc == i == 运行期 inst.pc`**。判空用 `c==0`（空槽带真实 `bd`），
  不是 `pn==0`。既有 `CE245/258/259` 等坐标不受影响。
- **地图坐标**：`map@<文件>@ev<号>@p<页>@pc<号>`。
  例：`map@SampleMapA.mps@ev0@p0@pc33`（新游戏问卷职业参数）；页条件见 §5.4。

### 3.2 magic 写法（本作 `crates/wolf-vm/src/magic.rs`）

| 写法 | 含义 | 例 |
|---|---|---|
| `2000000+v` | `var{v}`（可変DB[0] 通常变量） | `2000020 → var20 信頼` |
| `1000000+group*100000+slot` | `self[group*100+slot]`（事件 self 变量，**非平坦**） | **`1_600_010 → self[610]`，不是 `self[10]`** |
| `9000000+s` | `sys{s}`（系統DB[14] 系统变量） | `9000078 → Sys78 月` |
| `1100000000+row*100+col` | `cdb[0,row,col]`（CDataBase type0 单元格） | `1_100_001_209 → cdb[0,12,9]` 最大行动力 |
| `0..999999` | 字面量 | `3000` |

> self 组 6（`1_600_000 + i` → `self[600+i]`）专用于接收调用实参，见 §5.3。
> `1_000_000` 在 op121 里也可能是「字面乘数」而非存储地址，解码时须按上下文区分。

### 3.3 ★ 四个命名空间不得混用

| 命名空间 | 取值 | 出现处 | 说明 |
|---|---|---|---|
| **CE 号** | `0..349` | `CE<编号>@<pc>`、`op210 a[0]-500000` | 公共事件编号，0 基 |
| **map ev 号** | 各 `.mps` 内 `0..N` | `map@...@ev<号>@...` | 地图内事件号，**与 CE 号无关** |
| **v 号（var id）** | `0..301` | `var{v}`、`变量对照表.csv` 的 `v号` 列 | SysDatabase type14 行号 |
| **WOLF magic 数** | `1000000..` / `2000000..` / `9000000..` / `1100000000..` | 脚本 `a[]` 原始 `intArgs` | 编码了「存储种类 + 编号」，**不是 v 号本身** |

例：`v10`（v 号，四职业标志「学生」）／`2000010`（magic，等价 `var10`）／`CE@10`（CE 号）／
`map@X@ev10`（地图事件号）／`op210 a[0]=500010`（调用 CE10）——**五个「10」互不等价**。
写表时「变量ID」列填 `v号`，「脚本证据」列填 magic 原始值，不要互换。

## 5. ★ opcode 契约（本作 docs 原本缺 `OPCODE_SPEC.md`，此处补关键几条）

> 来源均为 `crates/wolf-vm/src/exec.rs` 等一手实现源码；数值由 `work/out/_op111_classify.json`
> 全库重算 0 违例（见 `01_事件逻辑清晰度检查.md §9.3`）。这些契约决定「条件/数值怎么读」，
> 读错会把有序分档误当逻辑与、把 max 误当 abs。

### 5.1 op111 整数条件分支：**首真命中的有序分档，非逻辑与**（`exec.rs:2544-2561`）

- `n = a[0] & 0xF`（条件数）；**bit4 (`0x10`) = has_else**。
- 第 `i` 个三元组 `(var, value, op) = a[1+3i], a[2+3i], a[3+3i]`（`i = 0..n-1`）。
- 逐条 `compare(lhs, value, op)`，**第一个为真即命中 `case #(i+1)` 并 break**；`n` 条全假走 else
  （`401` case 表 / `420` else / `499` 关块）。
- 操作符（`exec.rs:1686-1699` `compare()`）：`0 >`、`1 >=`、`2 ==`、`3 <=`、`4 <`、`5 !=`、`6 &`(按位与)。
- **两个易错点，务必分清**：
  1. **`17 / 18 / 19` 作为「操作符字段」** = 移植库 `==` 兜底（`compare()` 的 `_ => lhs==rhs`），
     **零售原语义 U**。`_ce_full.json` 本 CE 文件里操作符字段真实只出现 **12 次**（17:2 / 18:10 / 19:0）；
     `exec.rs:1696` 源码注释「44x」是**移植库跨全数据**（含地图事件/续作复用）的口径，不是本文件计数。
  2. **`a[0] = 17 / 18 / 19` 是「`n` + has_else」头字节，不是操作符 fallback**。
     全库 **986 处**（a0=17:367 / 18:70 / 19:549）：`a[0]=17` → `n=1` 且 `has_else=True`，
     `a[0]=19` → `n=3` 且 `has_else=True`。典型 `CE258@956` 的 `a[0]=17` 即「1 条件 + else」，
     条件为 `(var99,100,1 >=)`；`ev0 pc106` 的 `a[0]=19` 即「3 条件 + else」的场景门。
     **不要**把这 986 处误标成「操作符兜底」。

> 例：`[2, 2000021,200,1, 2000021,0,1]` = 「若 `var21>=200` → case#1；否则（`>=0`）→ case#2」，
> **不是**「`var21>=200` 且 `var21>=0`」。只有**多个单条件 op111 层叠**才等价于 AND。

### 5.2 op121 变量赋值（`exec.rs:1870-1922`、`exec.rs:1638-1682`）

- `a[0]` = dst、`a[1]/a[2]` = 两操作数、`a[3]` = `bits`。
- `bin = (bits>>12) & 0xF`；**`bin==6` → `rand(min,max)` 闭区间**（`rng.rs`，全库 **682 站点**）。
- `compound = bits & 0x0F00`（低 8 位 flag 已 mask）——按 `exec.rs:1638-1682` **真实表**：

  | mask | 运算 | mask | 运算 |
  |---|---|---|---|
  | `0x000` | `=` | `0x500` | `%=` |
  | `0x100` | `+=` | **`0x600`** | **`max=`（不是 abs）** |
  | `0x200` | `-=` | `0x700` | `min=` |
  | `0x300` | `*=` | `0x800` | `abs=` |
  | `0x400` | `/=` | `0x900..0xC00` | 角度/三角/开方（移植库扩展） |

  **`0x600` 是 `max=`（钳位上界）不是 `abs`**；CE132 音量行 `max(Sys100,0)` 再 `min(Sys100,120)`
  即此机制。
- `a[0] == 1100000000 && len(a) >= 7` → **DB 写入**：`a[4]=type`、`a[5]=row`、`a[6]=col`，
  写 `CDataBase[type,row,col]`（全库 6 站点）。
- `bits & 0x10000` 为 **range flag，未文档化标 U**（全库 75 条，`_op111_classify.json` 记
  `range_operand_a4` 并标 `undocumented`，不臆测语义）。

### 5.3 op210 / op211 / op300 调用（`exec.rs:2252-2300,2448-2458`、`command.rs:138-155`）

- `a[0]` = target：`500000..599999 → id = a[0]-500000`、`600000..699999 → id = a[0]-600000`；
  其余（含 SelfVar dynamic）**静态不可解析**（本库 op210 dynamic 10 处、op211 dynamic 2 处）。
- **`a[1]` 是 `param_status`，不是实参**（`crates/wolf-format/src/command.rs:138-155`：
  210/211/300 的第一个 `u32` 之后固定紧跟 `param_status` 字，Kaitai schema 的变量范围门控在本作数据上
  永不成立，照 schema 会失步）。
- **`a[2..]` 才是真参数**，写入**子事件 self 组 6**：`self[600+i]`（magic `1_600_000+i`），
  字符串实参进 `CSelf5..8`（`exec.rs:1324-1335`、`magic.rs:58-70`）。
- **op300** 不按编号、按 `s[0]` 事件名查标题（`CallByName`，`exec.rs:2448-2458`）；
  本库 1,158 调用点、503 个去重 (CE,name)，2 个缩放 helper 名未在 CE 标题表（unknown 8 调用点）。
- 全库调用点口径（`ce_callers.tsv`）：**4,031 = op210 2,869 + op211 4 + op300 1,158**；
  另有地图页 op210 注册 5 图 829 处（全 8 图 855，多出 26 来自未注册示例图），
  由 `map_full.json::map_to_ce_calls` 提供入边，不计入 CE→CE 表。

### 5.4 页条件 AND vs op111 首真分档（完全不同）

- `.mps` 事件页的 `conditions()` 之间是 **AND**：`mps.rs:476-486` `conditions_met()` 用
  `.iter().all(...)`，每个 enabled slot 必须同时成立；无 enabled 条件的页恒匹配（通常是 page0 兜底页）。
- 这与 **op111 的首真命中分档**是两套机制，**不可类比**：页条件是「静态门（是否让该页生效）」，
  不是运行时 op111 分档，也不是「触发条件」。页 `variable` 字段是 **WOLF magic 数**（如 `1000000==0`
  即 self[0]==0），不是 v 号。
- 操作符：页条件只用 `>=`(25) / `==`(173) / `<=`(3) / `!=`(7)；`>`、`<`、`&` 出货数据中未用。
- 全量页门字面量见 `work/out/map_events_conditions.tsv`（102 页）、`work/out/ev0_newgame.tsv`（367 槽）。

### 5.5 选择肢与块栈标记（P1-6 协议）

- `102` 选择肢、`103` 块名、`401/420/421` case 标记、`498/499` 关块。
- `crates/wolf-vm/src/program.rs::from_slots` 配对协议：**`111/112/102/170/176/179` 开块**、
  `401/420/421` 为 case、`499/498` 关块（112 是字符串条件，须独立开块）。
- P1-6 全库核得：条件块(111/112) + 选择块(102) 共 **4,535 个开块与 499 关块严格 1:1**，
  `unclosed_at_eof = 0`；`BASELINE.json:232-251` 的 `blocks=5470 / unclosed_blocks=0 / max_depth=25`
  与此一致。不要把 case 标记数（401=7,562）当成条件数。

## 8. 写正文时的三条铁律

1. **凡攻略值 ≠ 脚本值，一律用脚本值**：正文用「攻略作 X，实为 Y（`CE<编号>@<pc>`）」双列/脚注标注，
   不以 G 级观测近似值当定论；判定列写 `✎以脚本为准`。
2. **凡标 `U` / `—` / `◐` 的项**，正文只能写「资料不足/待核」，**不得编造确切数字**——
   尤其概率、掉率、隐藏参数（插入次数 / 高潮次数 / 独自 H 经验等 v 号待定位项）、
   逐动作消耗、敌人/战力类公式。`rand` 只给区间不给具体值，不写「第 N 抽必得」。
3. **成人内容一律中性技术表述**（场景名、解锁/触发条件、阈值、状态机、增量），遵守
   `AGENTS.md §6` 与本作内容安全约定，不写露骨描写。
