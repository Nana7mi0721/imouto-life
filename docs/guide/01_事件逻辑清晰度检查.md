## 4. 三个根因（为什么「说不清楚」）

**A. 事件层：「冒烟结果」≠「触发条件」，中间缺一层「调用方 → guard → 条件字面量」。**
`M3_EVENT_MAP.md` 给的是 92 CE 的冒烟计数（T：ID/名称/帧数/消息/选项数），`M3_EVENT_GRAPH.md` 只有**出边**（谁调谁）、无入边索引、无调用点 pc、无 guard；全作约 4856 个调用点里，只有 CE258 被 `M3_ENDINGS.md:33-41` 钉死一条半链（有调用方 pc、无调用点 guard、无分支 pc）。`EVENT_REACHABILITY.md` 是**可达性判定**（单读档卧室态、只证「日常态脚本能不能跑完」，§8 自承），不是触发条件。→ **92 CE 的「进入/解锁条件」0/92 完整**。

**B. 口径层：本作没有统一的证据分级与坐标约定。**
三套并存：`ENGINE_BEHAVIOR.md` 的 A/B/C、`TEXT_METRICS.md` 的「已定案/部分/待实测」、大纲的 [有]/[核]/[缺]；
`pc` 写法不一（`CE42 pc13` / `[13]` / `pc62`），无 `CE@idx` 约定、无「pc == dump 下标」声明；
`OPCODE_SPEC.md` 缺失，`op111 首真命中有序分档、非逻辑与` 这条关键契约只在 `exec.rs:2557-2560`，docs 从未写明。
→ 结果就是「每个数值回指到某表某行」无从落地，概率与阈值容易把有序分档误读成逻辑与（F 审 #4/#9/#10）。

**C. 工具链层：解码器有，全库一手结构化数据没有（与姊妹作的最大差距）。**
`wolf-format` 的 `CommonEventData::parse`（`commonevent.rs:119`）+ `Command{params,strings}`（`command.rs:113`）已把
「350 CE → 逐 pc → op111/op121 字面量」解在内存里，但 `wolf-cli`（`main.rs:397-575`）**没有任何 `dump-ce` 子命令**，
`assets --format json` 导的是资产/DB 单元格，`list` 只有槽数。全仓**无** `_ce_full.json` / `msgs101.json` /
`_op111_classify.json` 等价物；`event_reach/report.tsv`(391 行) 是**可达性摘要**、`re_all/` 是 Ghidra 伪码，都不是脚本命令流。
→ 姊妹作能直接对 `_ce_full.json` 解码做定稿 00–11，本作只能「逐 CE 明文探查 + 运行时冒烟」（F 审 #2/#11）。

**外挂根因（成本最低、5/6 路都撞到）：资料已在 `work/out/`，但没回流 docs、没被大纲索引。**
例：24 个门控事件的 S 级逐页条件字面量在 `tables_new.md:90-113`，大纲 `:338` 却标 [核]「条件需补」；
结局/内裤/怀孕的逐 pc 坐标在 `ce258.txt`/`ce259.txt`/`m3_endings.rs`，docs 零索引；
开局 ev0 全链是 D 路本轮临时反汇编才定位（产物按只读约定**未留存**）。
→ 这不是「要重挖」，是「要把已有 dump 落成可引用产物并登记」。

### 9.2 口径定案（下游必须遵守）

- **CE `id` 为 0 基 `0..349`**，`id == 数组下标 == CE编号`；`d[245]` 即 CE245。既有 `CE245/258/...` 坐标不受影响，**不做 +1 偏移**。
- **`cmds[i].pc == i == 运行期 inst.pc`**；空槽是 `c==0`（且 `pn==1`、带真实 `bd`），判空用 `c==0`，**不是** `pn==0`。
- op111：`n = a[0]&0xF`，bit4 (`0x10`) = has_else；`(var,value,op) = a[1+3i..3+3i]`；**首真命中有序分档 → case #(i+1)**，非逻辑与。
  操作符 `0 >,1 >=,2 ==,3 <=,4 <,5 !=,6 &`；`17/18/19` = **移植库 `==` 兜底、零售原语义 U**（`exec.rs:1696`）。
  `a[0]=17/18/19` 是「条件数 + has_else」，**不要**误当操作符 fallback（全库 986 处；`CE258@956` 的 `a[0]=17` = `n=1 + else`）。

- magic：`1_000_000+group*100_000+slot → self[group*100+slot]`（`1_600_010=self[610]` 非 `self[10]`）；`2_000_000+v → var{v}`；`9_000_000+s → sys{s}`；`1_100_000_000+row*100+col → cdb[0,row,col]`。
