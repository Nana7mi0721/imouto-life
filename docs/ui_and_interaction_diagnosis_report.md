# 《妹！生活 ～単色～》Godot 复刻版 UI 与交互问题排查及修复方案报告

- **对照基准**：用户实机截图（图 1 原版开场、图 2/3/4 Godot 复刻版实机、图 5 姊妹作 `+DLC v2.03` 顶栏参考）及当前代码 `HEAD 141c524`
- **技术栈前提**：本作 UI 由 **Rust (`wolf-vm` + `wolf-game`)** 解释原版公共事件字节码并维护 `Screen` 槽位（`240..252` 顶栏、`320/2300` 侧拉栏、`36000..36014` 气球对话框），**Godot (`GameView.gd`)** 仅负责将 `sprites / texts / overlays / energy` 绘制到 `1024×576` 画布并回传鼠标/键盘输入。

## 一、 问题排查与修复方案总览

### 1. 带选项对话：需额外点击才弹出选项，未还原“流式打字 + 选项同步弹出”
- **现状问题**：遇到“对话 + 选项”并存的场景时，当前版本必须等文字显示完并额外点击一次鼠标，才会弹出选项框；原版则是文字流式输出的同时选项框立即同步弹出。
- **真实代码根因**：
  - 在 `crates/wolf-vm/src/exec.rs` 与 `crates/wolf-game/src/game.rs` 中，`Opcode 101`（`ShowMessage`，进入 `WaitState::Message`）与紧随其后的 `Opcode 102`（`ShowChoices`，进入 `WaitState::Choice`）是串行执行的：VM 在 `101` 阻塞，直到宿主调用 `message_dismissed()` 后才会推进到 `102`。
  - 当脚本在 `101` 后紧跟 `102` 时，由于 VM 停在 `WaitState::Message`，`game.choices` 尚未生成，必须由玩家先点击一次关闭/推进 `101` 才会触发 `102`。
- **修复方案**：
  1. **字节码前瞻（Lookahead）**：在 `wolf-vm` 执行 `Opcode 101`（或 `CE 270` 气球文本写入）时，检查当前指令后紧邻的下一条有效指令是否为 `Opcode 102`（且中间无等待/分支指令）。
  2. **同步挂起与输入分流**：若紧跟 `102`，在打开 `101` 流式打字的同时预先解析并下发 `choices`（或让 `101` 与 `102` 进入联合等待态），期间点击选项行直接提交 `ChoiceReply::Index` 并连带关闭 `101` 消息；点击空白处仅加速补全当前流式文本，不吞掉后续选项点击。
- **证据等级**：`Confirmed`（基于 `exec.rs` `WaitState::Message` / `WaitState::Choice` 串行状态机）

### 2. 对话框形状错误 & 推进时瞬闪矩形半透明旧框
- **现状问题**：
  1. 原版对话框（图 1）为中央黑色半透明圆角胶囊框；当前实机（图 2、图 3）呈现为上下边缘羽化模糊的横向长条渐变矩形。
  2. 点击推进对话的瞬间，屏幕下方会闪现一个矩形半透明的旧版对话框。
- **真实代码根因**：
  - 本作对话框由 `CE 270` 绘制在 `Picture 36000`（底框）与 `Picture 36013`（正文），而非 Godot 的 `ColorRect`/`Panel`。
  - 形状呈宽条羽化，源自 `36000` 所使用的窗口/图片资源尺寸或 `picture.rs` / `expand_balloon_frame()`（`game.rs:1921-1946`）对 `36000` 宽高与窗口九宫格（`WindowFile`）的缩放计算偏差。
  - 点击推进瞬闪旧矩形框，是因为 `101` 切句瞬间原版原生消息层（`rendered_message_layout`）或 `CE 270` 重建 `36000` 之前存在单帧空档，导致原生半透明矩形底框与 `36000` 在交替帧中短暂曝光。
- **修复方案**：
  1. 核查 `CE 270` 创建 `36000` 时的贴图/窗口参数及 `picture.rs` 对 `36000` 的 `scale` / `window` 尺寸计算，确保与原版圆角底框比例一致，并把 `expand_balloon_frame()` 从渲染读取路径移至纯图元计算，避免跨帧状态污染。
  2. 在气球模式（`CE 270` 接管 `36000/36013`）激活时，彻底抑制原生 `101` 矩形底框的绘制与过渡帧回退，消除切句瞬闪。
- **证据等级**：`Confirmed`（图 2/3 实机截图 + `game.rs:1486, 1864-1946`）

### 3. 人名框黑块缺损、切换后空框残留、无名消息误显及文字未居中
- **现状问题**（见图 2、图 3 左下角）：
  1. “妹妹”人名框出现明显黑色缺块与左右截断；切换下一句人名消失时，残缺的灰底框体仍异常残留。
  2. 部分原版无说话人的旁白或系统消息也会弹出人名框。
  3. 人名文字在框内未居中，明显偏向上边缘。
- **真实代码根因**：
  - `CE 270` 用 `Picture 36008..=36012` 绘制人名框背景切片，用 `Picture 36014` 绘制人名文字（`game.rs:148, 1492`）。
  - **黑块与残缺**：`36008..=36012` 在切片拼接、`alpha`/混合模式或宽度随字数动态计算时出现遮挡/截断，且当说话人为空时 `CE 270` 未把 `36008..=36012` 同步隐藏或擦除。
  - **文字偏上未居中**：`textpic.rs` 对 `36014` 文本的基准线/顶部偏移（`PLAIN_TEXT_TOP_OFFSET` / `TEXT_TOP_NUDGE_RATIO`）与 `game.rs:1490-1497` 对 `36008..=36012` 的上移补偿未对齐，导致文字上浮贴近框顶边。
- **修复方案**：
  1. 当 `36014` 文本内容去除空白后为空时，在 `picture_quads()` / `CE 270` 同步隐藏 `36008..=36012` 全部人名框切片，彻底杜绝旁白/无名消息显示空框。
  2. 校准 `36008..=36012` 的拼接宽度与 `36014` 的水平/垂直居中锚点（使文字垂直中心对齐人名框中心，消除黑色缺块与截断）。
- **证据等级**：`Confirmed`（图 2/3 左下角实机现象 + `game.rs:148, 1490-1497`）

### 4. 妹妹头像位置错误：右下角异常大头像残留 & 左下角小头像向下裁切
- **现状问题**（见图 2、图 3）：
  1. 图 2 右下角突然出现一个巨大的妹妹头像/半身像，遮挡了右下角“数据”按钮，且与旧版半透明对话框闪现相关联。
  2. 图 2、图 3 左下角对话框旁的小头像位置偏低，下半部分被屏幕底边裁切。
- **真实代码根因**：
  - **右下角大头像**：`101` 对话或 `CE 270` 关联的立绘/大头像图片槽位未在日间普通对话中正确屏蔽或擦除，在旧框闪现的帧时序里被错误保留在右下角。
  - **左下角小头像裁切**：小头像槽位（`CE 270` 内的头像槽，如 `36001`）的 `anchor` 锚点或 `y` 坐标计算偏低（未与圆角对话框底边对齐），导致向下超出 `576 px` 屏幕底边。
- **修复方案**：
  1. 定位并修复普通对话流中触发右下角大头像槽位的绘制/残留逻辑，确保日常对话框仅保留左下角小头像。
  2. 校准左下角小头像槽位的 Y 轴锚点/坐标偏移（整体上移使头像底边或中心与对话框协调对齐），保证完整落在 `0..576` 安全区内。
- **证据等级**：`Confirmed`（图 2 右下角大头像、图 2/3 左下角小头像裁切）

### 5. 对话结束后末句对话框滞留（点击无法关闭）
- **现状问题**（见图 2 → 图 3）：对话脚本执行完毕并切换场景动作（妹妹从站立变为趴在床上看手机、时间推进至 `20:30`）后，最后一句“怎么了，哥哥。”的对话框、人名框与小头像仍滞留在屏幕底部，点击鼠标也无法关闭。
- **真实代码根因**：
  - 当 `Opcode 101` 结束、`WaitState::Message` 释放且 `SysVar 12`（`表示中`）归零后，`CE 270` / `CE 63` 未在最后一帧执行擦除 `36000..=36014` 槽位的收尾分支（或收尾分支的 `Erase` 渐隐未完成即被结束），导致 `Screen` 中仍残留最后一条气球框、人名框与头像图片。
- **修复方案**：
  - 在 `wolf-game` 确认本轮对话全部结束（`messages.is_empty()` 且无活跃的 `WaitState::Message` / `WaitState::Choice`，`SysVar 12 == 0`）且 `CE 270` 未在当帧主动重绘时，清理或触发擦除 `36000..=36014` 气球相关槽位，确保主界面恢复干净。
- **证据等级**：`Confirmed`（图 3 实机截图：`20:30` 趴床状态仍滞留 `19:30` 对话框）

### 6. 侧拉栏持续闪烁 & 鼠标离开后未自动缩回
- **现状问题**：
  1. 左侧边栏触发指示器在未交互状态下会持续闪烁，仅当光标移入判定区高亮时才停止。
  2. 侧拉栏展开（如拉出状态栏或物品栏）后，鼠标移出侧拉表显示范围时不会自动缩回。
- **真实代码根因**：
  - **闪烁问题**：`CE 238/239` 或 `SampleMapA` 对应并行事件在闲置状态下每帧反复重置侧栏图片透明度/高亮状态，或 `picture.rs` 动画帧切换未稳定保持静止态。
  - **自动缩回缺失**：当前 `crates/wolf-game/src/game.rs:2475-2548`（`try_side_panel_handle`）仅实现了点击三角把手（`STATUS_HANDLE_Y = 118..157`、`ITEM_HANDLE_Y = 260..297`）切换开合，完全没有实现“展开后监听鼠标坐标离开面板区域自动收起”的逻辑。
- **修复方案**：
  1. 排查闲置状态下驱动侧栏提示图片（`320` / `2300` 及相关指示槽）的并行事件/透明度逻辑，消除未悬停时的周期性闪烁，仅在光标悬停把手区时高亮。
  2. 在 `Game::frame()` 的输入处理阶段增加自动缩回逻辑：当 `side_panel_is_open(320)` 或 `side_panel_is_open(2300)` 为真且当前无阻塞弹窗时，检测 `self.mouse` 是否离开对应展开面板的矩形范围（可带短暂防抖帧数），若离开则自动调用 `start_panel_event(238, 0)` / `start_panel_event(239, 0)` 平滑收起。
- **证据等级**：`Confirmed`（`game.rs:2475-2568` 代码路径确认无自动缩回逻辑）

### 7. 新增行动力进度条：数值绑定错误且位置错放于“精力”下方
- **现状问题**（见图 2、图 3、图 4 vs 图 5）：
  - 当前重写版额外增加的白色进度条被画在右侧 `精力 3/3` 下方，且实际绑定的数据源是精力而非行动力（图 2 `行动力70/75` 时白条却是满格，因为 `精力 3/3` 是满的）。
  - 需求期望参考图 5 姊妹作（`+DLC v2.03`）效果：将该条放在**顶部状态栏中央**，紧邻 `行动力` 标签与数值之间（`行动力 [白填充/灰底进度条] 当前值/最大值`），且真实计量**行动力数值**。
- **真实代码根因**：
  1. `crates/wolf-game/src/game.rs:1751-1759`（`Game::hud_energy`）读取的是 `CData 0:12:6 / 7`，即**精力（`3/3`）**而非**行动力（`70/75`）**。
  2. `godot/scripts/GameView.gd:86-96, 646-656`（`_draw_energy`）把该条硬编码画在了 `Vector2(760.0, 34.0)`（正好落在 `精力 3/3` 正下方），且样式只画了白框+白条，未对齐图 5 的中央位置与灰底白填充样式。
  3. 同时注意：`CE 217` 绘制顶栏文本时，原版 `行动力70/75` 与 `熊头 强壮 哥哥 (学生)` 之间留白较宽，若要在顶栏中央放入进度条，需要协调 `CE 217` 顶栏文本槽位（`240..252`）的 X 坐标或由宿主调整行动力文本偏移，避免进度条压住文字。
- **修复方案**：
  1. **修正数据源**：核对 `CDataBase` / 全局变量中**行动力当前值与最大值**的真实索引（例如 `70/75` 对应的 `v[...]` 或 `CData` 字段），修改 `Game::hud_energy()` 返回行动力 `(current_ap, max_ap)`（并建议重命名为 `hud_ap()` 以免语义混淆）。
  2. **重定位与样式对齐**：参考图 5，将 `GameView.gd::_draw_energy()` 的绘制坐标从 `(760, 34)` 移至顶部栏中央区域（高度居中于顶栏、灰底白填充带细边框），并将 `CE 217` 的 `行动力` 标签与 `70/75` 数值文本分别置于进度条左右两侧。
- **证据等级**：`Confirmed`（图 2/4/5 截图对比 + `game.rs:1751-1759` + `GameView.gd:86, 646`）
